# Implementation Plan: Simple Employee Chat (Quick Reference)

## Overview

Add real-time chat functionality for employees using Socket.IO and Prisma.

## Quick Facts

- **Estimated Time**: 6 weeks
- **Complexity**: Medium-High
- **Breaking Changes**: None
- **New Dependencies**: `socket.io` (^4.6.1)
- **Database Changes**: 3 new models (ChatRoom, ChatMessage, ChatParticipant)

## Architecture Stack

```
Frontend → Socket.IO Client → Socket.IO Server → ChatService → Prisma → PostgreSQL
                              ↓
                         REST API Endpoints
```

## Database Schema (3 New Models)

1. **ChatRoom** - Direct or group chat containers
2. **ChatParticipant** - Many-to-many relation between rooms and employees
3. **ChatMessage** - Text messages with metadata

## API Endpoints Overview

### REST API (HTTP)
- `GET /v1/employee/chat/rooms` - List chat rooms
- `POST /v1/employee/chat/rooms` - Create room
- `GET /v1/employee/chat/rooms/:id/messages` - Get message history
- `POST /v1/employee/chat/rooms/:id/read` - Mark as read

### WebSocket Events
- `chat:join` - Join a room
- `chat:message` - Send/receive messages
- `chat:typing` - Typing indicators
- `chat:edit` - Edit message
- `chat:delete` - Delete message

## Key Features

✅ One-on-one direct chats
✅ Group chats
✅ Real-time message delivery
✅ Message history with pagination
✅ Typing indicators
✅ Read receipts
✅ Edit/delete messages
✅ JWT authentication for WebSocket

## Security

- JWT token authentication for WebSocket handshake
- Input sanitization (XSS prevention)
- Rate limiting (10 messages per 10 seconds)
- Authorization checks (room participation)
- Message content validation (max 5000 chars)
